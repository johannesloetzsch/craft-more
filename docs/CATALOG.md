# Catalog

Status: ⚪ planned · 🟣 draft · 🔴 mock · 🟠 poc · 🟡 prototype · 🟢 mvp · 🔵 mature — see [maturity-model](../skills/maturity-model/README.md).

## Core workflow
- 🔴 [`workflow`](../skills/workflow/README.md) 🌱 — Read back, think in the open, review early — your goal, your plan, your every step; craft, not slop
- 🔴 [`plan-build-workflow`](../skills/plan-build-workflow/README.md) 🌱 — One unit of work, done in the open: plan and grill it first, then build in small approved steps — nothing written without a go
- ⚪ `cost-budget-guardrails` 📄 — Token/permission budget, cheapest source first
- 🔴 [`tool-selection`](../skills/tool-selection/README.md) 🌱 — Move towards the goal with the right instrument — deliberately chosen by requirements

## Research
- ⚪ `environment-discovery` 📄 — Resource-efficient, non-intrusive environment probing
- 🔴 [`web-research`](../skills/web-research/README.md) 🌱 — Research strategy — set the goal first, then walk the source ladder from the cheapest to the most expensive source, naming each step along the way
- ⚪ `info-source-index` 📄 — Entry point: where to look first

## Session forensics
- 🔴 [`session-archaeology`](../skills/session-archaeology/README.md) 🌱 — See how a codebase was built — read session exports alongside git history and the repository's history log to trace provenance, order, and gaps, with honest confidence
- 🔴 [`session-replay`](../skills/session-replay/README.md) 🌱 — Rebuild what a session produced — reconstruct files and understanding from an export, choosing deliberately between 1:1 replay and interactive re-authoring, verified against the session's own records

## Learning loop
- 🔴 [`evaluation-report`](../skills/evaluation-report/README.md) 🌱 — A structured report of finished work with built-in reflection — whose proposed rules feed skill-evolution
- 🔴 [`maturity-model`](../skills/maturity-model/README.md) 🌱 — Make the maturity of a project — or any part of it — visible and honest: one status label from planned to mature, so quality claims are recognizable at a glance

## Meta & wrap-up
- 🔴 [`skill-authoring`](../skills/skill-authoring/README.md) 🌱 — Author new skills without drift — each one self-contained, reader-first, and every rule in a single home
- ⚪ `skill-discovery` 📄 — Find top skills from leaderboards and curators
- 🔴 [`skill-evolution`](../skills/skill-evolution/README.md) 🌱 — Every proposed rule gets a home — extend an existing skill, start a new one, or park it in the backlog
- ⚪ `name-discovery` 📄 — Interactive naming: criteria, conflict and domain checks

## Behavior & guardrails
- 🔴 [`uncertainty-and-verification`](../skills/uncertainty-and-verification/README.md) 🌱 — Verify whenever the actual purpose requires it — a protocol for keeping a shared, honest picture of how valid the information we process is
- ⚪ `step-sequencing` 📄 — Order steps for resource efficiency and interactivity
- 🟠 [`interaction-guard`](../skills/interaction-guard/README.md) 📡 — Keep the reply and the tool channel separate — answer in the reply, call a tool only for a named requirement, and stop the moment the user says so

## Audit
- ⚪ `audit-consistency` 📄 — Check the collection against its own conventions (headings, quotes, paths, links, catalog)

## Communication & style
- 🔴 [`parse-back`](../skills/parse-back/README.md) 🌱 — See the whole task at a glance — a live, marker-annotated outline opens every reply, so the goal, the settled facts, and the open questions are all visible in one look
- 🟢 [`emoji-markers`](../skills/emoji-markers/README.md) 🏁 — A fixed marker vocabulary for conversational output — one status marker (emoji plus uppercase word) tags each paragraph, and each parse-back node
- 🔴 [`communication-style`](../skills/communication-style/README.md) 🌱 — Give every message one predictable style — formatting, language, and names — so output stays easy to read and unambiguous
- ⚪ `language-selection` 📄 — Choose programming languages with justification
- ⚪ `coding-style` 📄 — Coding style conventions
